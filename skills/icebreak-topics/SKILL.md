# 破冰话题：从共同兴趣到聊天

这个 skill 回答一个问题：**两个分身此刻该聊什么。** 它不预测两个人会不会来电，只负责让对话开得自然、聊得下去。

## 文件

| 文件 | 内容 |
| --- | --- |
| `taxonomy.json` | 15 个兴趣大类、每个大类下的类型、默认属于哪一类 |
| `lexicon.json` | 归一化词表：同一个东西的不同说法，以及小众度 |
| `rules.json` | 五类权重、打分因子、7 条硬规则、8 条软规则、四个对话阶段 |
| `openers.md` | 每一类的开场白样例和反例 |
| `boundaries.md` | 共同讨厌能聊什么、不能聊什么 |

## 输入

双方的社交状态。兴趣需要是三级结构，每一条带热度、最近是否活跃和披露级别：

```json
{
  "interests": [
    { "category": "music", "type": "独立音乐", "entity": "某乐队", "level": 8, "recentAt": "2026-10-15", "disclosure": "match", "evidence": "这周循环他们新专" }
  ],
  "situations": [ { "text": "在备考", "expiresAt": "2026-12-31", "disclosure": "match" } ],
  "dislikes": [ "早八", "被剧透" ],
  "avoid": [ "前任" ],
  "skills": [ { "name": "吉他", "role": "expert" } ],
  "wantsToLearn": [ "做饭" ]
}
```

缺少 `entity` 时只能比到类型层；只有 `category` 时只能算 C 类。这正是人格卡需要拆成三级结构的原因。

此外还需要当前对话进行到第几轮。

## 步骤

1. **筛掉不能用的条目。** 去掉不满足 H1（没有证据）、H4（对方不可见）的条目，以及落在任一方 `avoid` 里的话题（H2）。
2. **归一化。** 用 `lexicon.json` 把别名对到 canonical，规则见其中的 `matching`。
3. **找共同点并分类。**
   - 同一个 entity → **A**
   - 同一个 type、不同 entity → **B**
   - 只有 category 相同 → 该大类的 `defaultClass`。大类默认是 B 时，只在类型层也重合才算 B，否则降为 C
   - 双方都有、且未过期的 situation → **E**
   - 一方的 skills 是另一方的 wantsToLearn → **D**
   - 双方都有的 dislike → 记为“共同讨厌”，单独处理（H5、S6）
4. **打分。** 话题分 = 类别权重 × 小众度 × 时效 × 双方热度。参数全部在 `rules.json` 的 `factors` 里。任一方热度低于 5 的条目不用于开场。
5. **按阶段挑话题。** 根据当前轮数查 `rules.json` 的 `stages`，从该阶段允许的类别里选分数最高的**一个**（H7）。
   - 破冰没有 A、E：用 B 并立即具象化（S3）
   - 所有分数都低于 0.2：用 S7，诚实地表示好奇
   - C 类只在邀约阶段使用（S4）
6. **生成消息。** 参考 `openers.md` 的写法，用主人的说话风格改写。生成后逐条检查硬规则 H1–H7，违反任何一条就重写。
7. **B 类具象化的后续。** 对方回答了一个具体对象：如果主人的社交状态里也有它，就升级为 A 继续聊；没有就进入互相推荐。

## 输出

```json
{
  "stage": "icebreak",
  "topic": { "class": "A", "item": "某乐队", "score": 1.25, "evidenceSelf": "这周循环他们新专", "evidenceOther": "…" },
  "message": "看到你也在听某乐队，新专你最喜欢哪首",
  "alternatives": [ { "class": "B", "item": "独立音乐", "score": 0.58 } ],
  "rulesFired": ["H1", "H2", "H7", "S1"],
  "sharedDislike": null
}
```

`rulesFired` 一定要记录。试点时用它统计每条规则命中后的结果：对方回复长度、聊了几轮、是否真人接管、接管后是否约了线下。没有效果的规则删掉，权重按数据调整。

## 用于匹配排序

把两个人所有共同点的话题分加起来（每一类最多计 2 条，防止一类刷分），作为排序里的“好聊度”。它只代表“开场好不好聊”，不代表“合不合得来”，展示给用户时写成“你们都在听某乐队”，不写成分数。

## 不做的事

- 不推断任何人没写的兴趣
- 不使用 MBTI 排序（S8 默认关闭）
- 不替真人确认任何线下见面
